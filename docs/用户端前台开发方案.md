# 用户端前台开发方案

## 1. 项目定位

当前项目已有一套后台管理系统，主要供基金会内部管理员、录入人员、审核人员使用。新增的用户端前台面向外部访问者和捐赠人，重点解决以下问题：

- 捐赠人可以查询自己的捐赠记录。
- 公众可以查看基金收入、支出、结余和明细。
- 捐赠人可以提交开票信息，由后台统一处理和导出。

用户端前台不承担后台管理职责，不直接暴露后台管理接口。

## 2. 推荐目录架构

建议保留现有后台前端，新建独立用户端前台目录：

```text
website project/
  backend/          FastAPI 后端，复用并扩展
  frontend/         当前后台管理端，内部人员使用
  portal/           新增用户端前台，外部用户使用
  docs/             项目文档
```

这样可以让后台管理端和用户端前台在路由、样式、权限、部署上保持清晰边界。

## 3. 技术选型

用户端前台建议继续使用现有技术栈：

```text
Vue 3 + Vite + Element Plus + Axios
```

理由：

- 与现有后台前端技术一致，维护成本低。
- 可以复用部分请求封装、格式化逻辑和构建经验。
- Element Plus 能快速支撑表单、表格、日期选择、分页等需求。

用户端视觉风格应与后台区分，避免侧边栏管理系统形态，采用更轻量的官网式布局。

## 4. 页面结构

第一版建议包含 4 个页面：

```text
/
  用户端首页

/donation-query
  捐赠查询

/fund-usage
  基金使用查询

/invoice-request
  开票申请
```

如果后续子基金较多，可扩展为：

```text
/fund-usage/:fundId
```

## 5. 页面说明

### 5.1 用户端首页

首页作为三个核心功能入口。

建议内容：

- 顶部导航：捐赠查询、基金使用查询、开票申请。
- 功能入口卡片。
- 简短说明文字，例如查询范围、数据更新时间、开票处理说明。

首页不建议做复杂营销页，第一版以清晰可用为主。

### 5.2 捐赠查询

功能目标：

- 用户输入捐赠人、时间范围、年份查询捐赠记录。
- 支持历年捐赠统计，展示该捐赠人累计捐赠笔数和累计金额。

查询条件：

- 捐赠人名称。
- 日期范围。
- 年份。

结果字段：

- 捐赠人。
- 捐赠日期，精确到年月日。
- 捐赠金额。
- 捐赠项目。
- 捐赠编号。

统计信息：

- 累计捐赠笔数。
- 累计捐赠金额。

安全要求：

- 不展示手机号、邮箱、证件号、后台录入人等敏感信息。
- 查询结果应分页。
- 后续建议加入验证码或查询码，降低被批量枚举的风险。

### 5.3 基金使用查询

功能目标：

- 展示主体基金和子基金的收入、支出、结余。
- 展示对应基金的收支明细表格。

顶部汇总：

- 总收入。
- 总支出。
- 基金结余。
- 文字说明。

明细表格字段：

```text
日期 | 项目说明 | 收入金额 | 支出金额
```

交互建议：

- 使用基金切换控件展示主体基金和子基金。
- 支持按日期范围筛选。
- 表格分页展示。

### 5.4 开票申请

功能目标：

- 用户填写开票所需信息。
- 提交后后台生成一条开票申请。
- 后台可查看、处理、导出 Excel。

表单字段：

- 捐赠人姓名或企业全称。
- 捐赠金额。
- 捐赠日期。
- 电子邮箱。
- 捐赠人联系电话。
- 个人身份证号或企业统一社会信用代码。
- 备注。

表单规则：

- 捐赠人、金额、日期、邮箱、联系电话、证件号为必填。
- 金额保留两位小数。
- 邮箱格式校验。
- 电话格式做基础校验。
- 提交成功后展示申请编号或提交成功提示。

## 6. 后台管理端扩展

为支撑用户端数据维护，现有后台管理端建议新增两个菜单。

### 6.1 基金使用管理

用于维护主体基金、子基金及其收支明细。

功能：

- 基金新增、编辑、启用、停用。
- 基金收支记录新增、编辑、删除。
- 按基金和日期筛选。

### 6.2 开票申请管理

用于处理用户提交的开票申请。

功能：

- 查看申请列表。
- 查看申请详情。
- 修改处理状态。
- 导出 Excel。

状态建议：

```text
pending    待处理
processed  已处理
rejected   已驳回
```

## 7. 开发阶段计划

### 第一阶段：用户端基础框架与捐赠查询

目标：

- 新建 `portal` 项目。
- 搭建首页、导航、路由、基础样式。
- 实现捐赠查询页面。
- 后端新增公开捐赠查询接口和统计接口。

交付：

- 用户可以按捐赠人、日期、年份查询捐赠记录。
- 用户可以查看累计笔数和累计金额。

### 第二阶段：基金使用查询

目标：

- 后端新增基金和基金收支记录数据模型。
- 后台新增基金使用管理页面。
- 用户端实现基金使用查询页面。

交付：

- 用户可以切换主体基金和子基金。
- 用户可以查看收入、支出、结余和明细表格。

### 第三阶段：开票申请系统

目标：

- 后端新增开票申请数据模型和接口。
- 用户端实现开票申请表单。
- 后台新增开票申请管理页面。
- 后台支持 Excel 导出。

交付：

- 用户可以提交开票申请。
- 后台可以查看、处理、导出开票申请。

### 第四阶段：安全与体验优化

目标：

- 增加验证码或提交频率限制。
- 完善敏感信息脱敏。
- 优化移动端体验。
- 增加基础验收脚本。

交付：

- 用户端适合公开访问。
- 查询和提交流程具备基础安全保护。

## 8. 验收标准

- 用户端三个核心功能均可访问。
- 捐赠查询结果准确，统计金额和笔数正确。
- 基金使用汇总和明细金额正确。
- 开票申请可以成功提交，并能在后台查看。
- 开票申请可以导出 Excel。
- 用户端不暴露后台敏感字段。
- 页面在 PC 和移动端均可正常使用。
