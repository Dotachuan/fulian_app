# 阿里云正式上线方案（小程序 + 后台）

## Summary

目标是把当前“本地 FastAPI + Cloudflare Tunnel 预览链路”切换为“阿里云 ECS 正式生产链路”，并完成微信小程序提交审核与上线。  
基于当前仓库和你刚确认的条件，这次采用以下默认方案：

- 部署形态：**单台阿里云 ECS**
- 地域：**中国大陆地域**
- 上线范围：**小程序 API + 管理后台**
- 域名规划：**`api.fulian520.com` 给后端，`admin.fulian520.com` 给后台**
- 运行方式：**Nginx + FastAPI(systemd) + MySQL(同机)**
- 当前 Cloudflare Tunnel：**仅保留给本地开发预览，不进入正式生产链路**

一个很重要的点：**小程序本身不是部署在服务器上的**。  
真正部署到阿里云的是：

1. 后端 API  
2. 上传图片与静态文件  
3. 管理后台前端构建产物  
4. MySQL 数据库

小程序代码则是构建后上传到微信公众平台发布。

## Key Changes

### 1. 先完成阿里云生产环境底座
建议购买并准备：

- `ECS`：Ubuntu 22.04 LTS，`2核4G` 起步，系统盘 `50GB SSD`
- 安全组开放：`22 / 80 / 443`
- 公网 IP：固定公网 IP
- 域名解析：
  - `api.fulian520.com` -> ECS 公网 IP
  - `admin.fulian520.com` -> ECS 公网 IP

服务器初始化统一按 Linux 生产方式落地：

- 新建普通运维用户，禁用 root 直连
- 安装 `Python 3.11+ / Nginx / MySQL 8 / Node.js 20 / Git`
- 配置时区、日志目录、自动重启、基础防火墙
- 仓库拉到固定目录，例如 `/srv/foundation-donation`

### 2. 后端改为正式常驻服务
当前仓库已具备生产化基础：

- 后端：`FastAPI + Uvicorn`
- 数据库：MySQL
- 上传目录：`backend/uploads`
- 公共资源地址：`PUBLIC_ASSET_ORIGIN`

正式部署时要完成这些配置：

- 生产 `.env`
  - `DB_HOST=127.0.0.1`
  - `DB_PORT=3306`
  - `DB_NAME=foundation_donation`
  - `DB_USER` / `DB_PASSWORD` 换成生产账号
  - `SECRET_KEY` 换成高强度随机值
  - `PUBLIC_ASSET_ORIGIN=https://api.fulian520.com`
  - `WECHAT_MINIAPP_APPID` / `WECHAT_MINIAPP_SECRET` 填正式值
  - `MEMBER_SMS_DEBUG_RETURN_CODE=false`
- 用 `systemd` 托管 FastAPI
  - 固定监听 `127.0.0.1:8000`
  - 开机自启
  - 崩溃自动拉起
- 生产数据库初始化
  - 建库建用户
  - 导入当前本地数据
  - 执行一次健康检查与登录检查

这里不再使用 Cloudflare Tunnel，生产流量直接走：

`微信小程序 / 管理后台 -> Nginx -> FastAPI -> MySQL`

### 3. Nginx 承接正式域名
Nginx 统一做四件事：

- `admin.fulian520.com` 提供后台前端静态站点
- `api.fulian520.com/api/` 反代到 `127.0.0.1:8000`
- `api.fulian520.com/uploads/` 暴露上传图片
- HTTPS 终止与 80 跳 443

建议拆成两个 server：

- `admin.fulian520.com`
  - `root` 指向 `frontend/dist`
  - 后台通过环境变量访问 `https://api.fulian520.com/api/v1`
- `api.fulian520.com`
  - `/api/` -> FastAPI
  - `/uploads/` -> 后端静态资源
  - `/health` 可公网访问用于检查

这一层要特别确认：

- 新闻封面、头像、证书素材上传后生成的 URL 都必须是 `https://api.fulian520.com/uploads/...`
- 不再出现 `127.0.0.1`、`http`、临时 tunnel 域名

### 4. 管理后台上线
当前后台是 `Vite + Vue`，正式上线很直接：

- 在服务器执行 `npm install` 和 `npm run build`
- 把 `frontend/dist` 交给 Nginx 托管
- 后台 API 基址改为生产域名
- 生产环境关闭开发态调试信息

同时要补一轮后台上线前检查：

- 管理员登录正常
- 新闻/公告/项目资讯/产业园链接管理正常
- 图片上传后地址为 `https://api.fulian520.com/uploads/...`
- 导入、开票、意见建议导出、绑定码导出可用

### 5. 小程序改为正式生产配置并发布
小程序不部署到服务器，但要切到正式生产域名并重新提审。

前端侧要确认：

- `miniapp/src/config/env.js` 的微信端接口基址最终走 `https://api.fulian520.com/api/v1`
- 所有图片、头像、新闻封面、证书素材都从 HTTPS 正式域名加载
- 不再依赖本地预览专用逻辑
- 保留 H5 调试配置，但与正式发布隔离

微信公众平台侧要完成：

- 服务器域名配置
  - `request 合法域名`：`https://api.fulian520.com`
  - `upload 合法域名`：`https://api.fulian520.com`
  - `download 合法域名`：`https://api.fulian520.com`
- 如仍需 `web-view` 打开公众号文章，确认：
  - 小程序与目标公众号已完成关联
  - 当前 AppID 对应主体有权限打开该公众号图文
- 上传正式构建包到微信开发者工具
- 设置版本号、体验版、提审、发布

### 6. 数据迁移与运维兜底
正式上线前必须补齐最小运维能力：

- 数据迁移
  - 导出本地 MySQL 数据
  - 导入生产 MySQL
  - 校验会员、捐赠、新闻、项目资讯、开票申请、建议反馈
- 文件迁移
  - 复制 `backend/uploads`
  - 确保历史新闻封面、头像、图片链接不失效
- 备份
  - MySQL 每日自动备份
  - `uploads` 目录每日打包备份
- 日志
  - Nginx access/error
  - FastAPI service log
  - MySQL error log
- 后续更新方式
  - 本地改代码
  - 提交 Git
  - 服务器 `git pull`
  - 后端重启 `systemd`
  - 后台重新 `build`
  - 小程序重新构建并上传新版

## Test Plan

### 生产上线前验收
1. `https://api.fulian520.com/health` 返回正常
2. `https://admin.fulian520.com` 可打开并正常登录
3. 后台上传图片后，生成地址为 HTTPS 正式域名
4. 小程序真机能正常请求接口，不再依赖 Cloudflare Tunnel
5. 小程序真机可加载新闻封面、头像、项目图片
6. 会员登录、绑定、我的捐赠、证书、开票申请、通讯录都可用
7. 意见建议提交成功，后台可查看并导出 Excel
8. 项目资讯“查看更多”可正常读取各自独立内容
9. 公众号文章链接在真机上可正常打开
10. 后台重启、服务器重启后服务能自动恢复

### 发布前回归
1. 后台新闻/公告/公益项目/产业园编辑不回归损坏
2. 文件上传、头像上传、证书生成不回归损坏
3. 旧数据中的图片链接没有残留 `127.0.0.1`
4. 微信开发者工具与真机表现一致
5. 小程序审核版本使用的是生产接口，不是本地接口

## Assumptions

- 你已经具备中国大陆服务器上线所需的备案条件
- 这次先不上 `portal` 公网，只上线“小程序 API + 管理后台”
- 生产环境先采用“单 ECS + 本机 MySQL”，后续再视访问量升级为 `ECS + RDS + OSS`
- Cloudflare Tunnel 后续仅用于本地开发演示，不作为正式生产入口
- 正式图片、头像、上传文件先继续存服务器本地磁盘，不在这一轮切 OSS
- 微信小程序当前使用的正式 AppID 就是仓库里已经配置的 `wx55a5e8ddfaf71404`
