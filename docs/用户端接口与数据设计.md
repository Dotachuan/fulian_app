# 用户端接口与数据设计

## 1. 设计原则

用户端接口应与后台管理接口分离。

原因：

- 后台接口需要登录鉴权，字段更完整。
- 用户端接口面向外部访问者，只应返回必要字段。
- 用户端查询接口需要脱敏、防枚举和参数限制。

建议新增公开接口模块：

```text
backend/app/api/v1/public.py
```

并在 `backend/app/main.py` 中注册：

```python
app.include_router(public.router, prefix="/api/v1", tags=["public"])
```

## 2. 公开接口设计

### 2.1 捐赠记录查询

```http
GET /api/v1/public/donations/query
```

查询参数：

```text
donor_name   string   必填，捐赠人名称
date_from    date     可选，开始日期
date_to      date     可选，结束日期
year         int      可选，年份
page         int      默认 1
page_size    int      默认 10，最大 50
```

返回示例：

```json
{
  "items": [
    {
      "donation_no": "DON202604200001",
      "donor_name": "张三",
      "donation_date": "2026-04-20",
      "amount": "1000.00",
      "target_name": "教育助学"
    }
  ],
  "total": 1
}
```

说明：

- 不返回 `donor_id`、`created_by`、`created_at`、`updated_at` 等后台字段。
- 不返回手机号、证件号、邮箱、地址。
- `donor_name` 可做模糊查询，但后续建议增加验证码。

### 2.2 捐赠人历年统计

```http
GET /api/v1/public/donations/summary
```

查询参数：

```text
donor_name   string   必填，捐赠人名称
year         int      可选，年份
```

返回示例：

```json
{
  "donor_name": "张三",
  "total_count": 8,
  "total_amount": "12000.00"
}
```

### 2.5 提交开票申请

```http
POST /api/v1/public/invoice-requests
```

请求体：

```json
{
  "donor_name": "张三",
  "amount": "1000.00",
  "donation_date": "2026-04-20",
  "email": "user@example.com",
  "phone": "13800000000",
  "identity_no": "110101199001011234",
  "remark": "需要电子票"
}
```

返回示例：

```json
{
  "id": 1,
  "request_no": "INV202604200001",
  "status": "pending",
  "created_at": "2026-04-20T12:00:00"
}
```

校验规则：

- `donor_name` 必填。
- `amount` 必填，保留两位小数。
- `donation_date` 必填。
- `email` 必填，符合邮箱格式。
- `phone` 必填。
- `identity_no` 必填。

## 3. 后台管理接口设计

### 3.1 开票申请列表

```http
GET /api/v1/invoice-requests
```

需要登录，建议管理员或操作员可访问。

查询参数：

```text
donor_name
status
date_from
date_to
page
page_size
```

### 3.2 更新开票申请状态

```http
PUT /api/v1/invoice-requests/{id}
```

请求体：

```json
{
  "status": "processed",
  "remark": "已开具电子票"
}
```

### 3.3 开票申请导出

```http
GET /api/v1/invoice-requests/export
```

导出 Excel，字段建议包含：

```text
申请编号
捐赠人姓名或企业全称
捐赠金额
捐赠日期
电子邮箱
联系电话
身份证号或统一社会信用代码
备注
状态
提交时间
处理时间
```

## 4. 数据模型建议

### 4.1 funds

基金表。

```text
id             int primary key
name           varchar(100) not null
type           varchar(20) not null    main / sub
description    varchar(1000)
status         varchar(20) not null    active / inactive
sort_order     int default 0
created_at     datetime
updated_at     datetime
```

### 4.2 fund_usage_records

基金使用明细表。

```text
id              int primary key
fund_id         int not null
record_date     date not null
project_desc    varchar(255) not null
income_amount   numeric(14, 2) default 0
expense_amount  numeric(14, 2) default 0
remark          varchar(1000)
created_at      datetime
updated_at      datetime
```

规则：

- 同一条记录可以只有收入或只有支出。
- 收入和支出都为空或都为 0 时不允许保存。
- 结余通过汇总收入减支出计算，不建议手工存储。

### 4.3 invoice_requests

开票申请表。

```text
id              int primary key
request_no      varchar(32) unique not null
donor_name      varchar(100) not null
amount          numeric(14, 2) not null
donation_date   date not null
email           varchar(255) not null
phone           varchar(50) not null
identity_no     varchar(100) not null
remark          varchar(1000)
status          varchar(20) not null    pending / processed / rejected
processed_at    datetime
created_at      datetime
updated_at      datetime
```

可选字段：

```text
donation_id     int nullable
```

如果后续需要将开票申请与已有捐赠记录绑定，可以增加该字段。

## 5. 与现有系统的关系

### 5.1 可复用能力

现有能力：

- 捐赠记录表。
- 捐赠人表。
- 捐赠目标表。
- 后台登录鉴权。
- Excel 导出能力。
- 操作日志能力。

可直接复用：

- 捐赠查询的数据来源。
- 捐赠金额、日期、目标等字段。
- Excel 导出的实现方式。

### 5.2 需要新增能力

必须新增：

- 用户端公开接口。
- 基金和基金收支明细模型。
- 开票申请模型。
- 后台开票申请管理页面。
- 后台基金使用管理页面。

建议新增：

- 公开查询验证码。
- 提交频率限制。
- 敏感字段脱敏工具函数。

## 6. 安全注意事项

- 公开接口不使用后台接口的完整响应模型。
- 捐赠查询必须限制分页大小。
- 不允许通过公开接口获取捐赠人联系方式和证件号。
- 开票申请中的身份证号、统一社会信用代码仅后台可见。
- 后台导出开票申请需要登录鉴权。
- 后续上线公网前建议增加验证码或限流。

## 7. 第一版实现优先级

优先级从高到低：

1. 公开捐赠查询接口和用户端捐赠查询页面。
2. 开票申请提交接口和用户端表单。
3. 后台开票申请列表和导出。
4. 基金使用数据模型和后台维护页面。
5. 用户端基金使用查询页面。
6. 验证码、限流、脱敏增强。
